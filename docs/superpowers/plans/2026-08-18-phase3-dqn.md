# Phase 3 DQN Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a hand-written Deep Q-Network agent over the 17-dim continuous state, with replay buffer and target network, plus the two required ablations and a comparison against tabular Q-learning.

**Architecture:** A new `DQNAgent` implements the existing `Agent` interface with `obs_kind = "cont"`, so `runner.run_episode` feeds it `state.featurise()` output with no change to the runner. Learning happens inside `update()`: push the transition to a hand-written ring buffer, then every `train_freq` steps sample a minibatch and take one Adam step on the Huber loss against a frozen target network. Nothing in Phase 0–2 is modified; the only edits to existing files are additive (a new dataclass and loader section in `config.py`, new keys in `training_default.yaml`, one new helper in `state.py`).

**Tech Stack:** Python 3.13, PyTorch 2.13.0+cpu, numpy 2.5.2, pytest 9.1.1. Interpreter is `.\.venv\Scripts\python.exe` — the global 3.13 lacks the project's dependencies.

**Spec:** `docs/superpowers/specs/2026-08-18-dqn-design.md`

## Global Constraints

- **No magic numbers in `.py` files** (CONSTRAINTS #9). Every tunable lives in `config/training_default.yaml`. Structural constants that are not tunable (e.g. the number of actions) may be module constants with a comment saying why.

- **Do not modify** `scripts/train.py`, `scripts/ablations.py`, `scripts/compare_agents.py`, `src/soc_triage/agents/tabular.py`, or any Phase 0–2 test (CONSTRAINTS #11, #18).
- **Train/eval seed separation is enforced in code**, not comments (CONSTRAINTS #2). DQN's block is `1000000`, ablations' is `1200000`; both must pass the existing distinctness check.
- **Files stay under 500 lines** (CONSTRAINTS #12).
- **Type hints on all public functions.** Docstrings on every algorithm name the update rule and the Sutton & Barto section.
- **Never claim a test passes without running it and showing the output** (CONSTRAINTS #16).

```python
def feature_scale_vector(scales: tuple[tuple[str, float], ...]) -> np.ndarray:
    """Order config's (name, divisor) pairs into a vector matching FEATURE_NAMES.

    The ordering check lives here rather than in config.py because this module
    owns FEATURE_NAMES, and because config.py cannot import state.py without a
    cycle (state.py imports EnvConfig).

    Silently accepting a partial mapping would leave one column unscaled — the
    network would still train and the bug would surface only as a worse result,
    so both a missing and an unknown name raise.
    """
    provided = dict(scales)
    missing = [name for name in FEATURE_NAMES if name not in provided]
    unknown = [name for name in provided if name not in FEATURE_NAMES]
    if missing or unknown:
        raise ValueError(
            f"feature_scales must name every column exactly once; "
            f"missing {missing}, unknown {unknown}"
        )
    return np.array([provided[name] for name in FEATURE_NAMES], dtype=np.float64)
```

```python
"""The replay buffer, tested as the ring buffer it is.

Roadmap calls this out as a classic interview question, so it is written by
hand (CONSTRAINTS #7) and every property an interviewer would probe is pinned:
capacity, overwrite order, sampling shape, and reproducibility under a seed.
"""

import numpy as np
import pytest

from soc_triage.agents.replay import ReplayBuffer

OBS_DIM = 4


def _fill(buffer, n, start=0):
    for i in range(start, start + n):
        buffer.push(
            np.full(OBS_DIM, float(i)), i % 5, float(i), np.full(OBS_DIM, float(i) + 0.5), False
        )


def test_length_grows_then_stops_at_capacity():
    buffer = ReplayBuffer(capacity=10, obs_dim=OBS_DIM, seed=0)
    assert len(buffer) == 0
    _fill(buffer, 4)
    assert len(buffer) == 4
    _fill(buffer, 20, start=4)
    assert len(buffer) == 10


def test_oldest_entry_is_the_one_overwritten():
    buffer = ReplayBuffer(capacity=3, obs_dim=OBS_DIM, seed=0)
    _fill(buffer, 5)  # pushes rewards 0,1,2,3,4 -> buffer should hold 2,3,4
    obs, action, reward, next_obs, done = buffer.sample(64)
    assert set(np.unique(reward)) == {2.0, 3.0, 4.0}


def test_sample_returns_declared_shapes_and_dtypes():
    buffer = ReplayBuffer(capacity=50, obs_dim=OBS_DIM, seed=0)
    _fill(buffer, 50)
    obs, action, reward, next_obs, done = buffer.sample(8)
    assert obs.shape == (8, OBS_DIM) and obs.dtype == np.float32
    assert action.shape == (8,) and action.dtype == np.int64
    assert reward.shape == (8,) and reward.dtype == np.float32
    assert next_obs.shape == (8, OBS_DIM) and next_obs.dtype == np.float32
    assert done.shape == (8,) and done.dtype == np.float32


def test_transitions_stay_aligned_across_the_five_arrays():
    """A ring buffer bug that shuffles one array relative to the others
    produces a plausible-looking batch of nonsense transitions, and nothing
    downstream would ever error."""
    buffer = ReplayBuffer(capacity=50, obs_dim=OBS_DIM, seed=1)
    _fill(buffer, 50)
    obs, action, reward, next_obs, done = buffer.sample(32)
    for i in range(32):
        step = reward[i]
        assert np.allclose(obs[i], step)
        assert np.allclose(next_obs[i], step + 0.5)
        assert action[i] == int(step) % 5


def test_same_seed_gives_identical_samples():
    a, b = ReplayBuffer(20, OBS_DIM, seed=7), ReplayBuffer(20, OBS_DIM, seed=7)
    _fill(a, 20)
    _fill(b, 20)
    for x, y in zip(a.sample(6), b.sample(6)):
        assert np.array_equal(x, y)


def test_different_seeds_give_different_samples():
    a, b = ReplayBuffer(200, OBS_DIM, seed=1), ReplayBuffer(200, OBS_DIM, seed=2)
    _fill(a, 200)
    _fill(b, 200)
    assert not np.array_equal(a.sample(16)[2], b.sample(16)[2])


def test_done_flag_survives_as_a_float():
    buffer = ReplayBuffer(4, OBS_DIM, seed=0)
    buffer.push(np.zeros(OBS_DIM), 0, 1.0, np.zeros(OBS_DIM), True)
    assert buffer.sample(1)[4][0] == 1.0


def test_sampling_an_empty_buffer_raises():
    with pytest.raises(ValueError):
        ReplayBuffer(4, OBS_DIM, seed=0).sample(1)
```

- [ ] **Step 3: Implement `src/soc_triage/agents/replay.py`**

Module docstring must state: this is uniform experience replay (Mnih et al. 2015;
S&B §16.5), written by hand per CONSTRAINTS #7, and explain the two things it
buys — breaking the correlation between consecutive transitions, and reusing each
transition more than once.

Implementation: five parallel numpy arrays sized `capacity` at construction, a
write cursor `self._cursor`, and a fill counter `self._size`. `push` writes at the
cursor, advances it modulo capacity, and raises `self._size` up to capacity.
`sample` draws `batch_size` indices uniformly **with replacement** from
`self._rng.integers(0, self._size, size=batch_size)` and returns the five arrays
indexed by them. `sample` raises `ValueError` when `self._size == 0`.

Comment the design choice: parallel arrays rather than a `deque` of tuples,
because sampling then returns contiguous arrays ready for `torch.from_numpy`
with no per-sample Python work, and the capacity semantics are two visible
integers instead of container behaviour.

- [ ] **Step 3: Implement `src/soc_triage/agents/dqn.py`**

Module docstring names the algorithm (Deep Q-Network, Mnih et al. 2015; S&B
§16.5 = function-approximation Q-learning §6.5 plus two stabilisers), writes the
update rule out in the same form `q_learning.py` uses, and explains why the
batched `max`/`gather` are tensor ops while the *structure* stays a readable
named sequence.

`update()` does, in order:

1. `self.env_steps += 1`
2. push `(scaled obs, action, reward, scaled next_obs, done)` to the buffer
3. return early if `len(buffer) < learning_starts` or `env_steps % train_freq != 0`
4. sample a batch — or, when `use_replay is False`, build a batch of exactly the
   one transition just observed
5. compute the target under `torch.no_grad()`:
   `target = reward + gamma * (1 - done) * max_a' Q_net(s')` where `Q_net` is
   `self.target` when `use_target_network` else `self.online`
6. `loss = F.huber_loss(online(obs).gather(1, action), target)`
7. `zero_grad()`, `backward()`, `clip_grad_norm_(..., grad_clip_norm)`, `step()`
8. `self.gradient_steps += 1`; if `gradient_steps % target_update_every == 0` and
   `use_target_network`, hard-copy `online -> target`

`done` semantics carried verbatim from `q_learning.py`: `done` means terminated,
never truncated.

`act()` scales the observation, and with probability `epsilon` returns
`self._rng.integers(0, n_actions)`, else the argmax of the network output with
**ties broken toward the lower action index**, matching `TabularAgent._argmax`
and `agents.dp.greedy_policy` so the learned policies stay comparable.

`end_episode()` mirrors `TabularAgent.end_episode` exactly — one decay step per
episode, floored at `epsilon_min` (D-015).

Seeding: `torch.manual_seed(seed)` before constructing the network,
`torch.set_num_threads(1)` at module scope with a comment that CPU determinism
is what makes the reproducibility test meaningful.
