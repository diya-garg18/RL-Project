# CONSTRAINTS.md — What must never happen

> Field Guide habit #7. "Allow" should never mean "allow anything." These are the boundaries that turn permission into *scoped* permission.
>
> **Do not edit this file without asking the humans first.**

---

## Scientific integrity — the non-negotiables

1. **Never let ground truth leak into an observation.** `Alert.is_true_incident` and `Alert.deadline_min` are known to the environment (it needs them to compute reward) and **never** to the agent. `state.py` must not encode them, directly or via a proxy. There is a test for this (`test_no_ground_truth_leakage`) and it must never be weakened or skipped.
   *The one exception:* the `oracle` baseline sees them by design — that's the point of an upper bound. It lives in `baselines.py`, it is named `oracle`, and it is never presented as a result we achieved.

2. **Training seeds and evaluation seeds are disjoint, and that separation is enforced in code**, not by convention. Never tune a hyperparameter by looking at evaluation-seed results.

3. **Never report a single run.** Every headline number is mean ± std over at least 5 seeds.

4. **Never delete or overwrite an experiment result** because a later run looked better. Append to `docs/experiments/EXPERIMENT_LOG.md`. If a run was wrong, mark it wrong and say why — don't erase it.

5. **A result that looks surprisingly good is a bug report until proven otherwise.** Investigate before celebrating, and write down what you checked.

6. **Negative results get documented, not deleted.** If an ablation shows a technique didn't help, that goes in the report.

---

## Code boundaries

7. **No Stable-Baselines3, RLlib, or any RL library for anything on the syllabus.** Q-learning, SARSA, Monte Carlo, DQN, REINFORCE, actor–critic and the reward model are written by hand. The students must be able to reproduce them in an interview. *(SB3 may be used as an optional cross-check for PPO only, and only if recorded in `DECISIONS.md`.)*

8. **No new dependency without asking.** `requirements.txt` changes require human approval.

9. **No magic numbers in code.** Every tunable value lives in `config/*.yaml`. If you're typing a number into a `.py` file that someone might want to change, it belongs in config.

10. **The environment never knows which agent is acting.** Agents never reach into environment internals. They talk only through `(state, action, reward, next_state, done, info)`.

11. **Nothing from a later phase may be required to run an earlier phase.** If Phase 5 breaks, Phase 2's results must still reproduce.

12. **Files stay under 500 lines.** Split when they grow.

---

## The teaching constraint

13. **Clarity beats cleverness, always.** If an implementation can't be explained to a fourth-year student in five minutes, it's the wrong implementation — even if it's faster or shorter.

14. **Prefer explicit loops in the learning algorithms** over dense vectorised one-liners, even at a speed cost. Optimise the *simulator* if it's slow; leave the algorithms readable.

15. **Never change the MDP definition without asking** — state buckets, the 5 actions, or the reward structure (`PROJECT_BRIEF.md` §3). The students have to defend these from memory; silently changing them undermines the entire preparation.

---

## Process

16. **Never claim something works without running it and showing the output.**

17. **One logical change per request.** Decompose big asks; don't produce a 500-line diff nobody will read properly.

18. **Don't build ahead of the roadmap.** Don't refactor code you weren't asked to touch.

19. **Never commit** `results/`, `*.pt`, `*.npy`, `.env`, or the preference-label database.

20. **No `Co-Authored-By` trailer on commits** (user's standing global instruction).

---

## Ethical / scope boundaries

21. **This is a defensive-security project and stays defensive.** It prioritises alerts for human analysts. It does not generate attacks, evade detection, or act autonomously on a real network.

22. **No real security telemetry, ever.** The simulator is synthetic. If a public dataset (CICIDS2017, UNSW-NB15) is used, it is only for calibrating feature distributions, and it is cited.

23. **If practitioner labels are obtained via Diya's KPMG contacts, no client or company-identifying information enters this repository.** Labels are anonymous: an opaque labeller ID, a choice, and a timestamp. Nothing else.
